# Ollama Builder (Minecraft 1.21.1, Fabric)

Мод связывает игровой чат с локальной нейросетью **Ollama** и строит структуры в мире.

Вы пишете в чат описание постройки — мод отправляет его в локальную модель, получает
строгий JSON со списком блоков и постепенно, по `blocksPerTick` блоков за тик,
возводит структуру перед игроком.

```
.print построй двухэтажный дом с двускатной крышей
```

---

## 1. Требования

| Компонент | Версия |
| --- | --- |
| Minecraft | **1.21.1** |
| Загрузчик | Fabric Loader **0.16.14** (минимум 0.16.0) |
| Fabric API | **0.116.17+1.21.1** |
| Yarn-маппинги | **1.21.1+build.3** |
| Java | **21** |
| Gradle | 8.10.x (Kotlin DSL), плагин Fabric Loom **1.8-SNAPSHOT** |
| Ollama | любая актуальная (https://ollama.com) |

> Про версию Loom: `1.8-SNAPSHOT` — последняя ветка, которая запускается на JDK 21.
> Более новые Loom (1.9+, 1.18+) требуют для **своей работы** JDK 22/25, хотя сам
> мод всё равно компилируется в Java 21. Если у вас стоит свежий JDK и хочется
> свежий Loom — поменяйте `loom_version` в `gradle.properties`.

Внешних библиотек у мода нет: HTTP — `java.net.http.HttpClient` из JDK,
JSON — Gson, который уже есть в игре.

## 2. Установка и запуск Ollama

1. Скачайте и установите Ollama: https://ollama.com/download
2. Запустите сервер (по умолчанию он слушает `http://127.0.0.1:11434`):

   ```bash
   ollama serve
   ```

   На Windows/macOS приложение обычно запускает сервер само.
3. Скачайте модель, указанную в конфиге (по умолчанию `qwen2.5-14b`):

   ```bash
   ollama pull qwen2.5-14b
   ```

   Модель должна уметь выдавать строгий JSON. Подойдут, например:
   `qwen2.5:7b`, `qwen2.5:14b`, `llama3.1:8b`, `mistral-nemo`.
   Чем слабее модель, тем чаще будут попадаться несуществующие блоки —
   мод их пропускает и пишет об этом в лог и в чат.
4. Проверьте, что сервер отвечает:

   ```bash
   curl http://127.0.0.1:11434/api/tags
   ```

> Если Ollama стоит на другой машине, поменяйте `host` в конфиге
> и убедитесь, что сервер слушает не только `127.0.0.1`
> (переменная окружения `OLLAMA_HOST=0.0.0.0:11434`).

## 3. Сборка мода

В проекте есть `gradle/wrapper/gradle-wrapper.properties`, но бинарный
`gradle-wrapper.jar` и скрипты `gradlew`/`gradlew.bat` в репозиторий не кладутся —
сгенерируйте их один раз любой установленной Gradle 8.x:

```bash
gradle wrapper --gradle-version 8.10.2
```

Дальше сборка обычная:

```bash
./gradlew build          # Windows: gradlew.bat build
```

Первый запуск качает Minecraft, Yarn-маппинги и Fabric API и перемаппит их —
это долго и требует памяти (в `gradle.properties` стоит `-Xmx2G`).

Готовый jar появится в `build/libs/ollama-builder-1.0.0.jar`
(файл `...-sources.jar` — это исходники, в игру его класть не нужно).

Запуск в разработке:

```bash
./gradlew runClient
```

Установка в игру: положите jar в `.minecraft/mods/` вместе с Fabric API.

## 4. Конфиг

Файл создаётся при первом запуске: `.minecraft/config/ollama_builder.json`

```json
{
  "host": "http://127.0.0.1:11434",
  "model": "qwen2.5-14b",
  "temperature": 0.3,
  "numPredict": 8000,
  "timeoutSeconds": 180,
  "blocksPerTick": 10,
  "maxBlocks": 600,
  "chatPrefix": ".print",
  "autoBuild": true
}
```

| Параметр | Смысл | Ограничения |
| --- | --- | --- |
| `host` | Адрес Ollama (схему `http://` можно не писать, завершающий `/` игнорируется) | — |
| `model` | Имя модели, как в `ollama list` | — |
| `temperature` | Температура генерации | 0.0–2.0 |
| `numPredict` | Лимит токенов ответа (`num_predict`) | 256–32768 |
| `timeoutSeconds` | Таймаут одного HTTP-запроса | 5–1800 |
| `blocksPerTick` | Сколько блоков ставится за один тик | 1–1000 |
| `maxBlocks` | Жёсткий потолок размера плана | 1–100000 |
| `chatPrefix` | Префикс команды в чате | непустая строка |
| `autoBuild` | `false` — план только сохраняется в файл, блоки не ставятся | — |

Конфиг читается один раз при старте. После правки файла перезапустите игру
(или переподключитесь к миру). Значения вне допустимых диапазонов и пропущенные
поля автоматически заменяются значениями по умолчанию — игра не упадёт.

## 5. Как пользоваться

### `.print <описание>`

Примеры:

```
.print построй двухэтажный дом с двускатной крышей
.print small stone watchtower with a ladder
.print 9x9 glass greenhouse
.print японский садик с прудом и мостом
```

Что происходит:

1. Сообщение **не попадает в чат** — событие отменяется.
2. Запрос уходит в Ollama асинхронно (отдельный daemon-поток, клиент не фризит).
3. Сырой ответ модели сохраняется в `.minecraft/ollama_builds/last_raw.txt`.
4. Разобранный план сохраняется в `.minecraft/ollama_builds/<timestamp>.json`,
   копия — в `.minecraft/ollama_builds/latest.json`.
5. Блоки ставятся по `blocksPerTick` штук за тик, на серверном потоке.
6. В чат приходит прогресс примерно раз в секунду и итог в конце:

```
[OllamaBuilder] Request sent to http://127.0.0.1:11434 (model: qwen2.5-14b)...
[OllamaBuilder] Plan saved: 20261015_180412_881.json
[OllamaBuilder] Building 347 blocks (10 per tick) at 128 64 -32
[OllamaBuilder] Placed 120/347 (35%)
[OllamaBuilder] Done: 347 blocks in 4.2s (skipped 0)
```

Обычный чат при этом работает как раньше — перехватываются только строки,
которые начинаются с `chatPrefix + " "` (и команда `.stop`).

### `.stop`

Немедленно отменяет текущую сборку и незавершённый HTTP-запрос:

```
[OllamaBuilder] Build cancelled: 120 blocks placed, 0 skipped
```

Если собирать нечего, придет `No active build`.

### Где появляется постройка

Якорь `(0, 0, 0)` из ответа модели — это **блок на уровне ног игрока в двух
блоках перед ним** (по горизонтали, с учётом диагонального взгляда).
Оси: `x` — вправо от игрока, `z` — вперёд, `y` — вверх. Отрицательных `y` не
бывает: координаты клампятся в `x, z ∈ [-32; 32]`, `y ∈ [0; 32]`.

Совет: перед командой встаньте на открытой площадке и смотрите туда,
где должна появиться постройка.

## 6. Файлы, которые создаёт мод

```
.minecraft/config/ollama_builder.json      # конфиг (создаётся с дефолтами)
.minecraft/ollama_builds/<timestamp>.json  # нормализованный план каждой генерации
.minecraft/ollama_builds/latest.json       # копия последнего плана
.minecraft/ollama_builds/last_raw.txt      # сырой ответ модели (для отладки парсинга)
```

Формат `<timestamp>.json`:

```json
{
  "generatedAt": "2026-10-15T18:04:12.881",
  "model": "qwen2.5-14b",
  "anchorX": 128, "anchorY": 64, "anchorZ": -32,
  "blockCount": 347,
  "skipped": 0,
  "blocks": [
    { "id": "minecraft:stone_bricks", "x": 0, "y": 0, "z": 0 }
  ]
}
```

## 7. Надёжность: что делает мод с «плохим» ответом модели

| Ситуация | Поведение |
| --- | --- |
| Ответ обёрнут в ` ```json ... ``` ` | Ограждения снимаются, JSON вырезается от первой `{` до последней `}` |
| Вокруг JSON есть поясняющий текст | Текст отбрасывается |
| JSON пришёл как экранированная строка | Строка разворачивается |
| Координаты написаны как `3.0` | Округляются до целых |
| `y < 0` или координаты вне лимитов | Клампятся к границам |
| Несуществующий блок / `minecraft:air` / id со свойствами или тегом | Блок пропускается, `skipped++`, запись в лог |
| Дубликаты по позиции | Дедупликация, «последний выигрывает» |
| Блоков больше `maxBlocks` | План обрезается, в чат приходит предупреждение |
| Блоков нет вовсе | В чат `Model returned no blocks`, файлы всё равно сохраняются |
| Ollama недоступна / HTTP 5xx / таймаут | До 3 попыток с задержками 1 с и 3 с, затем человекочитаемая ошибка в чат и в лог |
| Новый `.print` во время запроса | Предыдущий запрос отменяется (`cancel(true)`) |
| Новый `.print` во время сборки | Отклоняется: `Build in progress` |
| Чанк не загружен | Блок возвращается в конец очереди (не более одного возврата за тик, всего 3 попытки), затем пропускается |
| На позиции бедрок | Блок пропускается, бедрок не заменяется |
| Выход из игры / остановка сервера | Сборка сбрасывается, сетевой поток гасится shutdown-хуком |

Сетевые вызовы живут только в `ollama/OllamaClient.java` и выполняются в одном
daemon-потоке; в обработчиках тиков и клиентских событий блокирующих вызовов нет.

## 8. Структура проекта

```
build.gradle.kts                            # Loom, Java 21, зависимость от Fabric API
settings.gradle.kts                         # репозитории и версия плагина Loom
gradle.properties                           # версии MC / Yarn / loader / Fabric API
src/main/resources/fabric.mod.json          # метаданные мода, entrypoints main + client
src/main/java/com/example/ollamabuilder/
  OllamaBuilderMod.java                     # инициализация, события, shutdown-хук
  config/ModConfig.java                     # record + Gson, config/ollama_builder.json
  ollama/OllamaClient.java                  # HttpClient, таймаут, ретраи, отмена
  ollama/OllamaDto.java                     # record-ы запроса/ответа (TypeToken)
  prompt/PromptBuilder.java                 # SYSTEM_PROMPT + сборка user-сообщения
  parse/BuildPlan.java                      # record: блоки плана + якорь
  parse/BuildPlanParser.java                # санитайз, валидация, клампы, дедуп, файлы
  build/BuildQueue.java                     # очередь, курсор, счётчики, состояние, отмена
  build/BlockPlacer.java                    # END_SERVER_TICK, blocksPerTick/тик, чанки
  chat/ChatInterceptor.java                 # ClientSendMessageEvents.ALLOW_CHAT, .print/.stop
  chat/ChatFeedback.java                    # сообщения игроку (серверная сторона)
  util/BlockIds.java                        # id -> BlockState через Registries.BLOCK
```

> Важно про имена: проект использует **Yarn**-маппинги, поэтому в коде
> `ServerWorld`, `BlockPos`, `Identifier`, `Text`, `world.setBlockState(pos, state, Block.NOTIFY_ALL)`,
> `Registries.BLOCK`. Это точные Yarn-аналоги Mojmap-имён `ServerLevel`,
> `level.setBlock(pos, state, Block.UPDATE_ALL)` и `BuiltInRegistries.BLOCK`.

## 9. Диагностика

Логи: `.minecraft/logs/latest.log`, все записи мода помечены `[OllamaBuilder]`.

| Симптом | Что проверить |
| --- | --- |
| `не удалось подключиться к Ollama` | Запущен ли `ollama serve`, правильный ли `host`, не блокирует ли файрвол |
| `таймаут ответа Ollama` | Большая модель/длинный ответ — увеличьте `timeoutSeconds`, уменьшите `numPredict` |
| `Ollama вернула HTTP 404` | Модели нет локально: `ollama pull <model>` и сверьте имя с `ollama list` |
| `Model returned no blocks` | Загляните в `ollama_builds/last_raw.txt` — модель ответила не по схеме; попробуйте модель посильнее |
| `Skipped N invalid block(s)` | Модель выдумала id блоков; нормально для небольших моделей |
| Команда не срабатывает | Проверьте `chatPrefix` в конфиге и что после префикса есть пробел и текст |
| Ничего не строится, план сохраняется | В конфиге `autoBuild: false` |

## 10. Известные ограничения

- Целевой режим — **одиночная игра / встроенный сервер**. На выделенном сервере
  клиентская часть (перехват чата) не работает: `ALLOW_CHAT` — клиентское событие.
- Модель отвечает только списком блоков без состояний: двери, лестницы, ступени,
  факелы и т. п. ставятся в дефолтном состоянии и могут выглядеть «не так».
- Блоки ставятся «в лоб»: существующие блоки (кроме бедрка) заменяются.
- Структура не проверяется на связность — это задача модели и системного промпта.

## 11. Что проверено и как

Код проверен двумя способами:

1. **Компиляция настоящими артефактами 1.21.1.** Все 12 файлов собраны `javac --release 21`
   против реального `minecraft` 1.21.1 (client + server), перемаппенного Yarn
   `1.21.1+build.3`, `fabric-loader 0.16.14` и модулей `fabric-api 0.116.17+1.21.1`
   (`fabric-api-base`, `fabric-message-api-v1`, `fabric-lifecycle-events-v1`,
   `fabric-networking-api-v1`). Результат: **0 ошибок, 0 предупреждений** (`-Xlint:all -Werror`).
2. **Прогон логики: 209 проверок, все зелёные.** На стенде с заглушками классов
   Minecraft (сигнатуры — те же Yarn-имена) и с локальным HTTP-сервером,
   имитирующим Ollama, проверены:
   - конфиг: создание файла с дефолтами, частичный/битый/пустой конфиг, санитизация;
   - `BlockIds`: валидные id, `air`/`cave_air`/`void_air`, свойства блока, теги, мусор;
   - парсер: ` ```json `-ограждения, текст вокруг JSON, JSON внутри строки,
     координаты вида `3.0`, клампы, дедупликация, пропуск несуществующих блоков,
     обрезка до `maxBlocks`, пустой ответ, битый JSON, файлы `last_raw.txt` /
     `<timestamp>.json` / `latest.json`;
   - промпт: системная часть передаётся буквально, запрос игрока — без изменений;
   - `OllamaClient`: состав тела запроса (`model`/`prompt`/`stream:false`/`format:"json"`/
     `options.temperature`/`options.num_predict`), ретраи (ровно 3 попытки, задержка ~4 с),
     исчерпание ретраев, недоступная Ollama, таймаут, отмена активного запроса;
   - размещение: ровно `blocksPerTick` блоков за тик (10/10/5 на плане из 25),
     бедрок не заменяется, незагруженный чанк — 3 возврата и пропуск,
     догрузка чанка между тиками, отмена, защита от бесконечного «верчения» очереди;
   - чат: обычный чат и команды проходят нетронутыми, `.print`/`.print `/`.stop`
     подавляются, `.print` во время сборки отклоняется с `Build in progress`,
     якорь = уровень ног + 2 блока вперёд, прогресс и итог доставляются игроку,
     ошибка Ollama приходит в чат и не роняет игру.

Полноценный `./gradlew build` в окружении разработки не запускался: Loom при
первом прогоне перемаппит Minecraft и требует заметно больше 1 ГБ памяти,
а столько песочница не даёт. На обычной машине сборка идёт штатно.
